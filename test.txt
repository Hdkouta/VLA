カメラは Device 004 と 005 で認識されています。バス番号が不明なので、次で実際のデバイスファイルを確認してください。

```bash
lsusb | grep -i 2bc5
```

`Bus 002 Device 004` のように出ます。その番号を使って、権限を確認します。

```bash
ls -l /dev/bus/usb/002/004 /dev/bus/usb/002/005   # 002 は実際のバス番号に置き換える
```

見方は次のとおりです。

- `crw-rw-r-- root root` の場合は、一般ユーザーに書き込み権限がなく、open に失敗します。udev ルールを追加してください。
  ```bash
  echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2bc5", MODE="0666"' | sudo tee /etc/udev/rules.d/99-obsensor-libusb.rules
  sudo udevadm control --reload-rules && sudo udevadm trigger
  ```
  実行後に USB を抜き差しします。デバイス番号が変わるのが正常です。
- `crw-rw-rw-` の場合は、権限は問題ありません。次を確認します。
  ```bash
  lsusb -t                              # 480M なら USB2.0 接続で、帯域や電力が不足している
  sudo dmesg | tail -30                 # 接続時のエラーの確認
  ```

一時的に切り分けるなら、ルール追加の前に `sudo python dual_gemini_fast_capture.py` で動くか試す方法もあります。動けば、原因は権限で確定です。ただし venv の場合は `sudo $(which python) dual_gemini_fast_capture.py` と書いてください。

`ls -l` と `lsusb -t` の結果を貼ってください。
